**Method note (new this prune).** pytest's `<name>current` basetemp entries are directory JUNCTIONS and the harness
tests leave symlinked inboxes; `find -type f` (the manifest) does not enter them, `robocopy /E` does, so the first
copy of six items held duplicates on D: (for example 11,775 files against a 7,222-file manifest). `/MIR /XJ` did not
purge them. They were removed by listing every D: file absent from the manifest, checking that each lay under a
`*current` junction name or a symlinked harness inbox, deleting those, and re-verifying (md5 of every manifest file
plus source = manifest = destination counts). Two items (`wp4.6-window`, `wp4.6-window-dry`) and the loose files
were clean at the first copy. A future archive of a pytest basetemp should pass `/XJ` from the start and still
verify the counts.
