## The sample list (task ladder: one generator per group)

1. **Stills** (`stills.py`):
   - Content: uniform, horizontal gradient, and a near-zero red channel (red ≤ 2/255 over a
     blue-green scene). Each in 8-bit and 16-bit, with and without an ICC profile.
   - Profiles: a test-built Display P3 profile, the same construction as WP2.1S (built by the
     generator, never a third-party file), and sRGB from `ImageCms`.
   - Formats: PNG (16-bit through the WP2.1S stdlib writer), JPEG (8-bit), TIFF (8-bit, plus
     16-bit if Pillow writes it; else the ledger says so), HEIC (8-bit, plus 10-bit if
     pillow-heif encodes it).
   - Orientation: landscape and portrait. EXIF Orientation 1, 3, 6 and 8 on JPEG. On HEIC,
     the AD-24 cases: `irot` only, EXIF tag only, both, and neither.
   - Small sizes (for example 96 x 64), so everything is committed.
2. **The AD-14 flicker clip** (`flicker.py`):
   - Content: a still with a real-footage-like texture (ruling 1), repeated 90 frames at
     30000/1001 fps, with a bright disc of 10 % frame area moving across the lower third.
   - A mask of the measured region (the upper half), with a test that the disc never enters it.
   - Output: lossless (FFV1 in MKV, or a PNG sequence; the ledger says which) at 960 x 540 (ruling 2). Generated into `work/fixtures/`; only the mask and a manifest entry
     are committed.
3. **Video samples** (`video.py`, FFmpeg CLI). Each is a short clip (about 1-2 s) with a
   synthetic source (`testsrc2`/`smptehdbars` or the item-1 texture) and one AAC audio track
   (`sine`):
   - 8-bit HEVC yuv420p, tagged BT.709 full range like the HERO13;
   - 10-bit HEVC yuv420p10le;
   - HLG-tagged (`arib-std-b67`, `bt2020`);
   - PQ-tagged (`smpte2084`, `bt2020`);
   - untagged (no colour tags at all: the D54 case);
   - truncated (a valid clip with its tail bytes cut, so the readable portion and the fault
     both exist; state the cut);
   - VFR (D115: a stated pts sequence with at least two different frame durations, verified by
     ffprobe);
   - rotated (a display-matrix rotation of 90 degrees, verified by ffprobe).

   Committed only if each one is under the size limit; otherwise generated. Every sample's
   ffprobe facts (codec, pix_fmt, tags, frame count, pts list or its hash, rotation) go in the
   manifest. Truncation is checked by ffprobe reporting an error or a shorter stream.
4. **Dummy files** (`files.py`):
   - GoPro-style names (`GX010001.MP4`, `GX020001.MP4`, `GL010001.LRV`, `GX010001.THM`, plus
     lower-case variants) as tiny placeholders, for the D83 exclusion test. Chapter handling is
     deferred to v2 (v0.5.3), so the names exist only to be excluded or listed.
   - A DNG for D116: a minimal TIFF with the `DNGVersion` tag (50706), written with Pillow's
     `tiffinfo`. Two copies: one named `.dng`, one named `.tif` carrying the tag, for refusal
     by extension and by the tag (AD-17).
5. **Manifest** (`tests/fixtures/manifest.json`). Per sample:
   - id, path (committed, or generated with the command);
   - group;
   - the `Fault` kinds or `ProbeResult` facts it should produce, using WP2.2's names exactly;
   - the spec and V-test it serves;
   - the ffprobe or Pillow facts measured at generation;
   - its size, and its md5 when byte-reproducible.

   One schema, validated by a test.
6. **Pytest plugin** (`tests/fixture_plugin.py`):
   - session-scoped fixtures that return a committed sample's path, or generate a large one
     once into pytest's basetemp;
   - a `sample(id)` accessor driven by the manifest;
   - skips with a reason when FFmpeg is absent.
7. **Tests** (`tests/test_fixtures.py`):
   - every manifest entry exists or generates;
   - the measured facts match the manifest: tags, bit depth, rotation, VFR durations,
     truncation, ICC bytes, the EXIF Orientation and `irot` presence, the DNG tag;
   - regeneration is byte-identical for stills, the DNG and the manifest. Video is compared by
     decoded-frame hash, not file bytes;
   - **the size limit:** no file under `tests/fixtures/` over the limit, and the committed total
     under the cap (item 4);
   - **no owner material:** a test asserts no generator reads the footage root or any path
     outside its inputs. Static: no `local_config`/`find_footage_file` import in
     `tools/fixtures/`;
   - a planted defect fails by name: a mis-tagged sample, an oversize file, a manifest kind
     WP2.2 does not define.

## Rulings (CHARC `8d7880255daf7c79`, 2026-10-20)

1. **The AD-14 texture is fully procedural**, tuned to WP1.3's whole-frame statistics. The
   ledger quotes those statistics with their report line. No owner pixel is used.
2. **Flicker clip: 960 x 540, FFV1**, deterministic (seeded). The plugin generates it into
   `work/` on demand. Only the mask and the manifest entry are committed. The V3 consumer
   regenerates the clip when it is absent and verifies the decoded-frame hash against the
   manifest before use. Provide that check in the plugin.
3. **One `pytest_plugins = ["fixture_plugin"]` line in `tests/conftest.py`.** It is the only
   conftest change allowed. The WP-T1 guard stays untouched and its tests stay green.
4. **Size limits:** no committed file over 2 MB, and `tests/fixtures/` under 10 MB in total.
   A test enforces both.

## Declared operating envelope

Windows 11; FFmpeg 9.0.2 (gyan; libx265, libx264, FFV1); Pillow 12.3.0, pillow-heif 1.8.1,
NumPy as locked; no GPU; no footage. Out of envelope: other FFmpeg builds (byte-reproducibility
of video is not claimed; frame hashes are), other operating systems (generators are portable,
N1, but not run there).
