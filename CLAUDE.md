# Clearwater

Desktop tool (Python, PySide6) that corrects color cast, contrast loss and haze in amateur underwater photos (iPhone) and video (GoPro). Visual quality is the goal, not physically exact color. Single owner, Windows 11 laptop, open source (GPL-2.0-or-later), public repository since 2026-11-04 (1.0.0).

## Conventions (plan §2, §4)

- Environment: **uv** with a lock file. Python **3.12** (`.python-version`); confirmed against the chosen GPU and video libraries at the prototype gate. `uv sync` creates `.venv` with the `dev` and `comms` groups.
- Layout: `src/clearwater/` package, `tests/` (product tests; `tests/harness/` is the harness's own suite and is excluded from pytest), `tools/`, `docs/`.
- Tests: `uv run pytest`, markers `gpu`, `footage`, `gui`, `slow` (`--strict-markers`). Footage-marked tests skip when the footage path is absent. The full suite runs as the TWO-LEG gate (WP-T4, AD-28, 2026-10-28; WP-T6 `fullclip`, 2026-10-29): `uv run pytest -q -rs -n 4 --timeout 600 -m "not gpu and not footage and not gui and not slow and not fullclip" --basetemp=work/<run>-parallel > work/<run>-parallel.log 2>&1` then `uv run pytest -q -rs --timeout 1200 -m "(gpu or footage or gui or slow) and not fullclip" --basetemp=work/<run>-serial > work/<run>-serial.log 2>&1`, from Git Bash with `PYTEST_ADDOPTS` unset; collection identity parallel + serial + fullclip = all. The `fullclip` leg (`-m fullclip --timeout 2400 > work/<run>-fullclip.log 2>&1`, no `-n`, about 26 min: the seven gate tests on the whole GX011627 clip instead of its 90-frame trim) runs at least once per phase-end gate report and when a brief asks. Figures at WP-T6's gate (`fe65e6a`): parallel 5,312 / 1 in 714 s, serial 1,136 / 1 in 1,389 s (was about 2,260 s after WP-T5 and 3,331 s at WP-T4), so a package gate is about 35 min wall. The serial leg is the floor; a new wall-clock bound in a parallel-leg test is `slow` with a reason (fill GATE_CHECKS; `docs/reports/wp-t4-parallel-tests.md`, `docs/reports/wp-t6-gate-sizing.md`).
- Lint and format: `uv run ruff check .` and `uv run ruff format --check .` (Google docstring convention). Type checking: `uv run mypy` (strict, on `src/clearwater` and `tools`).
- Docstrings: Google style on every public function, class and module. Verify comments against the code they describe.
- Dependencies are added only through `pyproject.toml` and the lock file; a dependency not named in the architecture document needs the chief architect's approval (license check, spec N13).
- Keep code portable; nothing specific to one operating system without approval (spec N1).
- The footage folder is never written to, renamed in, or deleted from. All outputs go to the working folder. `tests/conftest.py` refuses to start pytest when its temp root (`--basetemp`, `PYTEST_DEBUG_TEMPROOT`, or the derived TMP/TEMP root) lies inside the configured footage folder (WP-T1, DR-21 closed; limits in DR-22). Never point a temp root there; `work/` is the legitimate basetemp.
- Distribution since 1.1.0 (owner's word 2026-11-06): a PyInstaller ONE-FOLDER Windows build (`tools/package/build.py`, CP6a = onedir, spec N14) and the tag-driven GitHub Actions release workflow `.github/workflows/release.yml` (a DRAFT release the owner publishes; AD-38; `docs/release-checklist.md` v2). No installer and no signing. The test gate still runs on the laptop; the workflow runs the parallel leg only.
- Commit by pathspec (`git commit -m "..." -- <paths>`); every role shares the main tree's index. Conventional commits carrying the work-package id.

## Definition of done (plan §4.5)

A work package is done only when: scope met within its owned files with frozen interfaces unchanged; docstrings complete; ruff, mypy and pytest pass; the verification loop has run until a full pass finds nothing new (suspect → confirm independently → fix → repeat); no assumptions were made where the brief or spec was ambiguous (stop and ask instead); a completion report is written; and an independent reviewer has checked it against the brief and spec. The concrete review and gate mechanism is `docs/review-gate-clearwater.md`.

## Hardware rule (plan §4.3)

**Desktop input rule (2026-11-04, after a WP6.1 incident):** no cell or seat sends synthetic keyboard or mouse input to the desktop (SendKeys, SendInput, keybd_event, AppActivate, mouse_event or equivalents). A GUI check uses UI Automation on Clearwater's own window elements, Qt's offscreen platform and test hooks, PrintWindow for a screenshot of Clearwater's own window, or the owner by hand. A stray keystroke lands in whatever the owner has in front.

**Entry-point isolation rule (2026-11-04, after two more WP6.1 incidents: a library re-entered the frozen executable and reached the GUI branch; a before-record test run against an old revision started the source GUI against the owner's real profile for up to 120 s):** any test, probe or before-record run that calls a product entry point (`clearwater.__main__`, `app.main`, the export worker; in-process or in a child; on ANY revision, old or new) first redirects APPDATA, LOCALAPPDATA and the XDG variables to a disposable root AND blocks the GUI (the PySide6 / shiboken6 imports blocked or `app.main` stubbed), with a bounded timeout. Before a run against an old revision, grep the test file for entry-point calls and confirm the rule holds there. No run activates the GPU pack until the frozen `-m` handler is in the build under test. The owner's real profile under `%APPDATA%\Clearwater` is never edited by a cell or seat, even to undo a stray line. **Recorded exception (owner's word 2026-11-05, "record the QUIT_SCRIPT exception"; WP6.3b turn 3):** an existing integration test whose purpose IS the real GUI start (`tests/test_app_startup.py` `QUIT_SCRIPT`) may import PySide6 and run the event loop, under redirected roots, `QT_QPA_PLATFORM=offscreen` and a bounded timeout, at the SEAT in a gate leg only; no cell runs it on any revision.

Agents run on the owner's laptop with direct access to the graphics card. Packages that record timing or memory figures are exclusive: one at a time, nothing else heavy running, timed on a full clip rather than one frame.
